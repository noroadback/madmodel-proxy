# 故障取证

用于排查请求延迟、`fetch failed`、工具参数无效、断流和交付超时。诊断默认关闭；开启后显示详细计时、独立核对上游参数并保存有限的失败记录，诊断开关本身不改变模型请求、重试策略或工具参数。

## 开启

当前请求结束后停止代理，在项目目录中设置环境变量并重新启动。

PowerShell：

```powershell
$env:PROXY_DIAGNOSTICS = "1"
npm start
```

macOS / Linux：

```sh
PROXY_DIAGNOSTICS=1 npm start
```

继续正常使用客户端。再次报错时，保留故障时间和代理日志中的 `诊断=...` 编号。每次上游尝试单独编号，对应记录位于 token 所在目录的 `failure-diagnostics.jsonl`，默认是 `~/.madmodel-proxy/`。

未发生失败尝试的成功请求不落盘；工具参数重试最终成功时，首次失败记录仍会保留。记录约到 1 MiB 时轮换，上一份为 `failure-diagnostics.jsonl.previous`，最多保留这两份。排障完成后删除 `PROXY_DIAGNOSTICS` 环境变量并重启即可关闭取证。

## 如何判断

### 请求计时

默认成功日志显示总耗时、token 用量、首字和单次输出速度。设置 `PROXY_DIAGNOSTICS=1` 并重启后，额外显示 `阶段[...]` 和上游响应 ID。阶段时间单位为毫秒，缺少观察点时显示 `—`。

| 字段 | 计时范围 |
|---|---|
| `本地` | 请求进入至预算预检就绪，包含接收请求体 |
| `分词` | 本地计数总耗时，包含排队 |
| `分词排队` | 等待计数线程的时间 |
| `提交` | 请求进入至本机 HTTP 客户端发完请求体 |
| `待上游` | 发完请求体至收到上游响应头 |
| `思考首段` / `正文首段` | 请求进入至收到首段非空思考或正文 |
| `生成` | 首个有效输出至收到 `[DONE]` |
| `背压` | HTTP 写入等待客户端可写的累计时间 |

各区间可能重叠，不能相加。提交事件不证明上游已收齐或开始计算；上游返回完整 JSON 时，没有增量生成区间。

`上游id` 对应响应中的 `id`。与客户端比较速度时，先对齐同一请求，再核对输出 token 数和起止时间；跨请求平均值可能采用不同口径。首字仍从原请求进入起算，重试后的提交和生成数据只对应最终尝试，背压时间累计所有尝试。

### 工具参数无效

| 记录 | 可以确认的范围 |
|---|---|
| `validation` 为 `json-incomplete` 或 `json-invalid`，`wire.complete` 为 `true`，`argumentComparison` 为 `match` | 独立解析原始上游响应得到的参数，与代理聚合参数一致；无效 JSON 已存在于代理收到的上游响应中 |
| `argumentComparison` 为 `mismatch` | 原始参数与代理聚合结果不一致，应检查代理解析与聚合；先核对该诊断编号对应的失败尝试 |
| `forwardingComparison` 为 `match` | 代理接收的参数与交给 HTTP 写入层的参数一致，不表示客户端已经收齐 |
| `forwardingComparison` 为 `mismatch` | 代理接收与写出记录不一致，需要检查交付路径，也可能是写入被取消或中断 |
| `wire.finishReason` 为 `length` | 上游报告长度限制结束；结合参数错误与请求预算判断是否因生成预算耗尽 |
| `argumentComparison` 为 `unavailable` 或 `wire.complete` 为 `false` | 本次证据不足，不能据此归因。可能是缺少结束标记、非标准事件、编码错误或取证限额 |

`wire.sawDone` 表示独立观察到的 SSE 终止标记；上游以完整 JSON 返回的备用响应没有这一标记。`wire.tools` 保存每个调用的索引、参数字符数和片段数，零片段表示上游没有提供参数增量。`not-checked` 表示没有进行该项对照。

原始参数和聚合参数即使一致，也只能定位到“上游响应已经无效”，不能继续区分模型生成错误与上游服务组装错误。要确定学校服务内部的原因，仍需要上游日志。客户端是否执行或把失败参数带入历史，也需要结合客户端的同次记录判断。

客户端需识别错误终态并丢弃失败调用，不执行工具或将失败参数带入后续对话；完整缓冲模式也需要正确处理错误。

### 工具参数重试

工具参数重试默认开启，与取证开关独立；设置 `PROXY_TOOL_RETRY=0` 并重启可关闭重试及首段暂存。满足下述条件时，代理按原请求重新生成整条回复，不补写参数、不添加提示，也不执行工具。

只有同时满足以下条件才会重试：

- 上游响应完整结束，明确给出 `stop` 或 `tool_calls`，没有结束状态冲突；SSE 必须收到合法 `[DONE]`。
- 每个调用都对应请求中唯一声明的 function 工具，调用字段与 ID 合法且无冲突，且请求未设置 `tool_choice: none`。
- 至少一个调用的参数仅为一个 `{` 及前后 JSON 空白，其余调用的参数均为合法 JSON 对象。
- 尚未向客户端发送响应头或写出任何模型帧，且本次客户端请求尚未进行过工具参数重试；流式 SSE 的首段暂存还须尚未开始释放。

客户端使用流式响应、上游返回 SSE，且本次尝试允许工具参数重试并声明了 function 工具时，首段最多暂存 250 ms、8192 字节或 32 帧。250 ms 从首个进入暂存队列的数据帧起算，任一上限到达即释放；收到 `{` 和 JSON 空白以外的参数字符也立即释放。少量正文或思考可能一起短暂等待。首段开始释放后即不再重试，即使帧仍在等待写入。

`PROXY_TOOL_STREAM=buffered` 模式中的工具参数仍需完整缓冲，不受上述首段上限限制；可提前交付的正文或思考仍可能短暂暂存。非流式聚合与 JSON 备用响应采用相同的完整性和参数判定，但没有上述首段暂存窗口。缺少 `[DONE]` 的 SSE、`length`、网络错误、字段或 ID 错误、空参数字符串，以及带键名或键值的残缺 JSON，均不触发工具参数重试。

每个客户端请求最多进行一次工具参数重试，认证重试不重置这个次数；非流式聚合的 `PROXY_NONSTREAM_TOTAL_MS` 时限也不会因工具参数重试重置。客户端只收到最终尝试。重试可能增加一次上游请求和相应用量，仍可能失败。

触发时日志记录 `tool-arguments-retry`，最终成功日志包含 `工具参数重试=1`。开启取证后，即使重试成功，首次失败仍保留诊断编号和失败记录；日志中的“参数转发=未转发”表示参数尚未交给 HTTP 写入层。客户端收到的 `usage` 属于最终成功的尝试。重试成功时，日志累计值包含两次尝试的有效用量；最终失败或缺少用量时，累计可能少于实际消耗，未知用量不会补零。

### 网络失败

普通网络错误日志中的 `request` 包含连接、上传和等待响应头，不能单凭这个字段区分三者；`response-body` 表示读取上游响应，`delivery` 表示向客户端交付。开启取证后，`networkStage` 根据本机观察到的传输事件进一步区分以下阶段。

| 记录 | 含义 |
|---|---|
| `networkStage: before-body-sent` | 尚未观察到完整请求体提交给本机 HTTP 传输层；可能处于连接或上传阶段 |
| `networkStage: awaiting-headers` | 已观察到请求体提交，尚未收到响应头；不证明远端服务已经收齐或执行请求 |
| `networkStage: response-body` | 已进入上游响应读取阶段 |
| `networkStage: delivery` | 失败时正在向客户端交付或等待客户端读取，不能误认成上游空闲 |
| `networkStage: unobserved` | 当前运行时未提供可关联的传输事件，不能把缺少事件当作未发送 |

`codes` 保留有限的底层错误码。`ECONNRESET`、`UND_ERR_SOCKET` 表示连接中断线索；DNS、证书等错误通常有对应错误码，但仅凭错误码不能判定是哪一台网络设备导致故障。可按同一时间对照系统网络事件及上游日志。

`network` 中的 `createdMs`、`bodySentMs`、`headersMs` 是相对本次上游请求开始的本机观察时间，缺失表示未观察到。`upstreamElapsedMs` 从本次上游请求开始计到结果返回，包含期间的客户端背压等待；`elapsedMs` 还包含结果返回后的校验或最终交付等待。`requestBytes` 是序列化请求体大小，不表示远端已收到的字节数。

发生网络错误时，上游可能已经收到整个请求。代理不会仅凭 `fetch failed` 自动重发，以免重复生成；客户端已有的重试行为不受此开关影响。

## 保存内容与限制

记录包含诊断编号、时间、错误类别、网络阶段和错误码、字节与片段计数、结束原因，以及参数对照结果。不保存完整对话、参数正文、参数哈希、凭据、请求 URL 或原始异常消息。比较使用的参数摘要只保留在该请求的内存中。

取证独立解析原始上游响应。工具参数默认实时交付，首段暂存例外见上文；非标准事件、损坏编码或过大事件会使取证结果降为无法核对。最多核对 64 个工具索引，每个事件受 1 MiB 取证限额约束；取证不会改写请求或补全参数。

该记录与 `DUMP_FAILED` 不同。开启取证不需要开启 `DUMP_FAILED`，后者会保存完整请求正文。提交排障材料前，选择对应诊断编号的记录即可；不要提交 token、creds 或完整请求文件。

历史故障如果没有保存底层错误或原始上游证据，之后的成功测试无法补回当时的数据。这套取证用于在下一次故障发生时留下可核对的证据。
