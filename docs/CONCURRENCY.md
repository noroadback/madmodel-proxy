# 上游并发实测

## 测试条件

2026-10-28 使用同一账号，经校园网直接请求学校 Chat Completions 接口。输入为合成短文本，关闭思考，使用流式响应和 256 token 输出上限。每组请求同时发起，组间顺序执行；成功以完整收到 `[DONE]` 为准。

## 实测结果

| 请求组合 | 发起数 | 完整成功 | 明确并发 429 |
|---|---:|---:|---:|
| DeepSeek V4.1 | 2 | 2 | 0 |
| DeepSeek V4.1，4 路首次测试 | 4 | 3 | 1 |
| DeepSeek V4.1，4 路复测 | 4 | 3 | 1 |
| DeepSeek V4.1，3 路复测 | 3 | 3 | 0 |
| Qwen | 3 | 3 | 0 |
| Qwen | 4 | 4 | 0 |
| DeepSeek V4.1 × 2 + Qwen × 2 | 4 | 4 | 0 |

两次拒绝均为 HTTP 429，JSON 错误码为 429，消息为“您的同时进行中的请求过多，请等待已有请求完成后再试”。同组其余请求正常结束。

另有一组 3 路 DeepSeek 请求在 60 秒内未收到响应头，测试主动中止，未列入上表。该组未收到限流错误，原因未确认。

## 结果范围

- **DeepSeek V4.1**。本次观测支持所测账号存在 3 路并发限制。
- **Qwen**。4 路全部完成后未继续增加，上限未确认。
- **混合模型**。4 路均完成，但生成阶段未全部重叠，无法据此确定后端同时执行数或跨模型计数规则。

本次仅测试一个账号和校园网直连路径，未验证其他账号、IP、WebVPN 及长请求。上游策略可能调整。

使用建议见 README 的[并发与限流](../README.md#并发与限流)。
