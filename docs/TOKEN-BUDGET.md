# 上下文预算

输入与输出共享模型的上下文窗口。`config.js` 中的模型配置给出参数预算上限，实际生成长度还取决于上游服务。

## 预留规则

- 用随包分发的 DeepSeek 词表估算文本，计入历史思考和工具字段。
- 在本地计数之外，预留 1,024 token，以及每项工具定义 20 token 的模板余量。
- Qwen 额外预留本地输入估算的 20%，补偿不同词表与模板造成的偏差。
- 每张图片单独预留 16,384 token。代理不下载或解码图片，纯文本请求不承担这部分预算。

接近窗口上限时，代理收缩显式指定的输出预算；未指定 `max_tokens` 时不注入默认值。估算输入与余量已经超过窗口时，返回 413 并提示缩短对话。

这些数值用于预留预算，实际用量仍取上游返回的 `usage`。图片按张估算，具体开销随分辨率和上游处理方式变化，仍可能超出预留量。

## Qwen 校准记录

2026-10-10 使用合成文本、关闭思考并要求简短回复，对照 `qwen3.8-27b` 返回的输入用量。下表比较的是 DeepSeek 本地计数与上游实际计数，尚未加入预算余量。

| 样本 | 本地计数 | 上游输入 | 上游 / 本地 |
|---|---:|---:|---:|
| 英文记录 | 2,017 | 2,217 | 1.099 |
| 中文记录 | 2,317 | 2,417 | 1.043 |
| JavaScript | 3,617 | 3,897 | 1.077 |
| JSON | 3,145 | 3,429 | 1.090 |
| 多语言混合 | 2,517 | 2,417 | 0.960 |
| 重复汉字 | 767 | 778 | 1.014 |
| 重复英文字符 | 1,041 | 1,052 | 1.011 |
| 英文长文本 | 62,017 | 70,917 | 1.144 |

最长样本的上游计数比本地高约 14.4%。当前采用 20% 的额外余量，并保留通用模板余量；这组样本不能代表所有文本或未来上游版本。

同日的灰度 PNG 图像探测中，各请求的本地文本计数均为 21 token，上游总输入如下。

| 图片尺寸 | 上游输入 |
|---|---:|
| 32 × 32 | 98 |
| 512 × 512 | 290 |
| 1,024 × 1,024 | 1,058 |
| 2,048 × 2,048 | 4,130 |
| 4,096 × 4,096 | 16,418 |

图片开销随尺寸增长，因此单独预留预算。上表统计整次请求的输入 token，包含文字、模板和图片。

修改后，英文长文本的输出预算从 262,000 收缩为 186,699，4,096 × 4,096 图片请求收缩为 244,710。两次真实请求均成功，上游实际输入与发送的输出预算之和均低于 262,144。

Qwen 的输出参数上限保留为 262,000。此前短文本探测在 262,104 附近被拒，该配置保留边界余量；实际请求还需扣除输入与上述预留量。

## 长对话与多图验证

2026-10-11 针对 [Issue #7](https://github.com/noroadback/madmodel-proxy/issues/7)，通过校园网直连测试 `DeepSeek-V4.1-Flash`。使用合成记录和图片，关闭思考，最多输出 8 token；每次更换系统提示前缀，成功请求中上游报告的缓存命中均为 0。

| 请求 | 上游输入 token | 首字等待 | 结果 |
|---|---:|---:|---|
| 约 50 万 token 文本 | 511,999 | 59.4 秒 | 完整成功 |
| 约 97 万 token 文本 | 972,797 | 162.8 秒 | 完整成功 |
| 64 MiB 四图请求 | 4,031 | 7.6 秒 | 完整成功 |
| 128 MiB 八图请求 | 未返回 | 未返回 | nginx 返回 HTTP 413 |

最长文本在约 4.5 秒收到响应头，随后约 158.3 秒没有响应体数据，超过原有 65 秒空闲限制。当前将响应头、空闲等待和工具补救默认时限设为 300 秒，给冷启动留出余量；这些测试不能保证所有负载都在该时限内完成。

图片为有效的 2,048 × 2,047 RGB PNG，使用无压缩编码构造大请求，JSON 尾部以少量空白补齐到精确的 64 MiB 或 128 MiB。这验证请求传输与图片解析，图片尺寸对应的上下文开销仍由上游决定。

64 MiB 成功与 128 MiB 被拒，只说明这两个样本的结果，不能据此确定上游的准确上限。代理默认接收 64 MiB，包括 JSON 和 Base64 图片；接收、解析与转发会产生内存副本，多图并发时应留出更多内存。

通过修改后的代理重测，另一组 972,799 token 的请求在约 162.8 秒返回首字并正常结束；64 MiB 四图请求约 8.7 秒完成。

### 前缀缓存对照

同日用约 13 万 token 补测连续对话。首次请求未命中缓存，首字等待 11.7 秒；保留系统提示和原有历史，追加一轮追问后，131,079 个输入 token 中有 130,816 个命中缓存，首字等待降到 0.64 秒。再次发送相同请求时为 0.73 秒。

DeepSeek 请求的前缀可被上游缓存复用，代理保留这项行为。固定系统提示、工具定义和已有历史，把新问题追加在末尾，有助于复用缓存。缓存容量、保留时间与请求路由由上游决定；这组 13 万 token 的结果不能直接外推为 100 万 token 的等待时间。
