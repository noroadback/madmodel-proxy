# madmodel-proxy

将[清华大学 DeepSeek 服务](https://madmodel.cs.tsinghua.edu.cn/)接入兼容 OpenAI Chat Completions 的客户端，并自动续期登录凭据。需要清华大学统一认证账号。

支持 Windows、macOS 和 Linux。推荐 [Node.js 24 LTS](https://nodejs.org/)，最低 18.14；无需 `npm install`。

[快速开始](#快速开始) · [模型配置](#模型配置) · [日常使用](#日常使用) · [常见问题](#常见问题) · [更新](#更新) · [高级配置](#高级配置)

## 快速开始

安装 Node.js 后，在终端执行：

```sh
git clone https://github.com/noroadback/madmodel-proxy.git
cd madmodel-proxy
npm run login
npm start
```

按提示完成统一认证，必要时完成二次认证。首次启动选择网络方式：校园网内选直连，校外或不确定时选 WebVPN。选择会保存，日常只需 `npm start`。

在客户端填写：

| 配置项 | 值 |
|---|---|
| API 类型 | OpenAI Chat Completions |
| Base URL | `http://127.0.0.1:8080/v1` |
| API Key | 默认可填 `local`；开启鉴权后填写配置的密钥 |
| 模型 | 获取列表后选择，或手填下方的模型 ID |

客户端需支持自定义 Base URL 和 Chat Completions；仅支持 Responses 接口的配置无法直接接入。

<details>
<summary>没有 Git，或使用 Windows</summary>

- **没有 Git**。在仓库页面选择 **Code → Download ZIP**，解压后在项目目录打开终端，从 `npm run login` 开始。
- **Windows 登录**。建议使用 PowerShell 或 CMD；无法确认密码隐藏的 Git Bash 终端会提示更换终端。
- **Windows 启动**。登录后可双击 `start.cmd`，或运行 `create-shortcut.cmd` 创建桌面快捷方式。

</details>

## 模型配置

优先在客户端获取模型列表；不支持获取时，完整复制以下 ID。

| 模型 ID | 输入 |
|---|---|
| `DeepSeek-V4.1-Flash` | 文字、图片 |
| `qwen3.8-27b` | 文字、图片、视频 |
| `DeepSeek-R1-W8A8` | 文字 |

根据学校服务公告，DeepSeek-V4.1-Flash 已于 10 月 18 日完成升级，现由 `deepseek-v4.1-flash-1017` 版本提供服务；调用方式保持不变，无需修改任何配置。媒体能力来自 2026-09-30 实测，工具调用、思考开关与响应字段于 2026-10-18 在 1017 部署上复核。客户端也需支持发送对应媒体。

- **工具调用**。DeepSeek V4.1 和 Qwen 支持原生调用，R1 实测未返回原生调用。
- **思考**。DeepSeek V4.1 和 Qwen 默认开启，可用 `reasoning_effort: "none"` 关闭。R1 无法关闭，只接受 `low` / `medium` / `high`。
- **响应模型名**。上游在响应里回显部署名（2026-10-18 实测为 `deepseek-v4.1-flash-1017`），与请求用的模型 ID 不同。严格比对两者是否相同的客户端会看到差异。
- **用量字段**。DeepSeek 的 `usage.prompt_tokens_details` 在含图请求中会给出 `image_tokens`，命中前缀缓存时会给出 `cached_tokens`；纯文本或未命中缓存时该对象仍可能为 `null`。Qwen 的输入用量只提供 `prompt_tokens`，不提供图片或缓存明细。

学校可能调整模型名称和能力，代理会在凭据有效后自动探测。默认配置下也可打开[本机模型列表](http://127.0.0.1:8080/v1/models)；修改端口后同步修改地址，开启鉴权后请通过客户端获取。

<details>
<summary>上下文与输出预算</summary>

以下为当前代理配置，单位为 token。客户端选择流式或非流式时，均使用同一预算。

| 模型 | 上下文上限 | 输出预算上限 |
|---|---:|---:|
| DeepSeek V4.1 | 1,048,576 | 1,048,576 |
| Qwen | 262,144 | 262,000 |
| R1 | 163,840 | 163,840 |

输入与输出共享上下文，代理按输入占用和预留余量下调过大的输出预算。图片估值不会单独触发本地拒绝；表中预算不保证实际生成长度。计量规则、上游限制与实测记录见[预算说明](docs/TOKEN-BUDGET.md)。

</details>

## 日常使用

保持运行窗口开启，按 Ctrl+C 停止。自动续期成功后无需重启；学校要求重新认证时，再运行 `npm run login`。

以下命令在项目目录的另一个终端中执行：

| 操作 | 命令 |
|---|---|
| 查看状态 | `npm run status` |
| 重新登录或更新密码 | `npm run login` |
| 手动续期一次 | `npm run once` |
| 清除本机凭据（先停止服务） | `node refresh-token.js logout` |

日志记录上游返回的有效 token 用量，有明细时附加图片和缓存计数；这些明细已包含在输入总量中，不重复累计。工具参数重试成功时，客户端收到的 `usage` 属于最终尝试，代理累计包含两次尝试的有效用量。最终失败或缺少用量时，累计可能少于实际消耗；未返回的用量保持未知，累计值在代理重启后归零。

首字从请求进入代理算起，直到收到首个有效输出。输出速度按首次有效输出至上游结束的时间计算，排除首字等待；数值受网络分块和缓冲影响，表示代理观察到的上游输出速度。首字等待小于 5 s 为绿，5 s 至不足 10 s 为黄，10 s 及以上为红。重定向默认输出纯文本，可用 `NO_COLOR=1` 或 `FORCE_COLOR=0` 关闭颜色。计时细节见下方排障参数。

凭据默认保存在 `~/.madmodel-proxy/`，与项目目录分开；`logout` 不撤销学校侧会话。服务默认仅监听本机且不校验 API Key，同机能访问端口的程序和用户均可调用。开启鉴权或供其他设备访问，见[局域网部署](docs/DEPLOY-LAN.md)；存储方式与数据流向见[安全说明](SECURITY.md)。

### 校内 / 校外切换

在运行窗口输入 `campus` 切到校园网直连，输入 `offcampus` 切到 WebVPN，回车生效。切换会重启服务并保存选择，未完成的请求需重试。

Windows 也可运行 `.\start.cmd campus` / `.\start.cmd offcampus`。服务已运行时，这两个命令只保存选择，下次启动生效。

### 并发与限流

2026-10-29，单账号独占、校园网直连实测，各模型并发上限如下：

| 模型 | 实测上限（路） | 建议客户端并发 |
|---|---:|---:|
| `DeepSeek-V4.1-Flash` | 3 | 1–2 |
| `qwen3.8-27b` | 4 | 2–3 |
| `DeepSeek-R1-W8A8` | 1 | 1 |

各模型的上限及超出 1 路的档位均测试两轮，超出部分返回并发 429。三模型合计 8 路的两轮测试全部完成，响应流有共同重叠区间。本次观测支持按模型分别限流；其他账号和网络路径未验证，上游策略可能调整，详见[并发实测记录](docs/CONCURRENCY.md)。

同一账号在其他会话、客户端或网页中的未完成请求也应计入。收到并发 429 后，等待已有请求结束再重试；持续失败时逐步延长重试间隔。代理不会对此类错误自动排队或重试。

本地另有 64 路并发上限和默认 256 MiB 的请求体总量保护，超限同样返回 429；这些限制用于保护本机资源，不代表上游额度。

## 常见问题

| 现象 | 处理方式 |
|---|---|
| 连接被拒绝 | 运行 `npm run status`，确认代理已启动，客户端端口一致 |
| 端口被占用 | 检查是否已有代理运行；换端口时设置 `PROXY_PORT`，并同步修改客户端地址 |
| API Key 缺失或无效 | 开启鉴权后需填写服务端配置的密钥 |
| token 过期或 401 | 确认 watch 在运行，等待自动续期；持续失败时运行 `npm run login` |
| 模型不存在 | 重启代理并重新获取模型列表，更新客户端选择 |
| 无法添加图片 | 检查客户端是否支持图片，并开启对应模型的图片输入选项 |
| “服务器繁忙”或 429 | 降低并发并稍后重试；持续失败时用短对话和默认参数验证，见[并发与限流](#并发与限流) |
| 400，上下文超限 | 缩短对话、减少历史图片或降低输出上限 |
| 413 | 减少图片或缩短对话；本地请求体默认上限为 64 MiB，上游另有限制，具体见报错 |
| 502、504 或回复中断 | 尝试缩短对话或切换网络；校外请使用 `offcampus` |
| `network-error` / `fetch failed` | 查看同条日志的失败阶段与底层错误码，含义见下方排障参数 |
| `stream-invalid-tool-call` | 丢弃失败调用后重试；结合 JSON 错误类别、结束原因与参数转发一致性排查 |
| 工具未执行 | 使用支持工具的模型，确认客户端提供并允许调用工具，检查是否等待执行确认 |

## 更新

先停止服务，提交或备份自己修改的项目文件，再执行 `git pull` 并重新启动。升级后在客户端重新获取模型列表。

ZIP 用户请解压到新目录，并重新创建桌面快捷方式。同一系统账户下通常可沿用默认凭据；自定义状态目录需继续使用原路径。版本检查只提示，不会自动更新文件。

## 高级配置

环境变量在启动前设置，修改后重启生效。以更换端口为例，客户端地址也需改为 `http://127.0.0.1:8081/v1`。

<details>
<summary>修改端口示例</summary>

PowerShell：

```powershell
$env:PROXY_PORT = "8081"
npm start
```

macOS / Linux：

```sh
PROXY_PORT=8081 npm start
```

</details>

| 变量 | 默认值 | 用途 |
|---|---|---|
| `PROXY_PORT` | `8080` | 本地端口 |
| `PROXY_UPSTREAM` | 按网络选择 | 完整上游 Chat Completions URL |
| `PROXY_BIND_HOST` | `127.0.0.1` | 监听地址；非回环地址必须配置密钥 |
| `PROXY_API_KEYS` | 未设置 | 逗号分隔的访问密钥 |
| `PROXY_BODY_LIMIT_MB` | `64` | 请求体上限，单位 MiB，包含图片数据 |
| `PROXY_BODY_BUDGET_MB` | `256` | 上传和处理中请求体的总量预算，单位 MiB，至少为单请求上限 |
| `PROXY_NO_UPDATE_CHECK` | 未设置 | `1` 关闭启动时的版本检查 |
| `MADMODEL_STATE_DIR` | `~/.madmodel-proxy/` | 凭据与状态目录 |

`PROXY_UPSTREAM` 会接收对话和 Bearer token，仅配置可信服务。该变量在启动时优先于网络选择；运行窗口中的 `campus` / `offcampus` 可覆盖当前地址，下次启动仍以环境变量为准。

请求体总量按原始 JSON 字节计量，额度保留到请求处理结束，容量不足时返回 429。解析、转发和分词另有内存开销，该预算不代表进程内存上限。

<details>
<summary>超时、续期与排障参数</summary>

时间参数单位为毫秒。长对话冷启动可能数分钟后才出首字，实际等待还受客户端与上游连接限制。

| 变量 | 默认值 | 用途 |
|---|---|---|
| `PROXY_HEADER_MS` | `300000` | 等待上游响应头 |
| `PROXY_IDLE_MS` | `300000` | 等待上游数据，包含首帧等待 |
| `PROXY_STREAM_TOTAL_MS` | `1200000` | 收到响应头后的上游响应总时限；最终回复交付另受同值限制 |
| `PROXY_NONSTREAM_TOTAL_MS` | `600000` | 非流式聚合总超时，工具参数重试不重置计时 |
| `PROXY_TOOL_STREAM` | `incremental` | 工具参数实时转发；`buffered` 在完整校验后交付工具参数 |
| `PROXY_TOOL_RETRY` | 开启 | `0` 关闭仅剩 `{` 和 JSON 空白的工具参数单次重试及流式 SSE 首段暂存 |
| `PROXY_STRIP_TOOLS_FOR` | `/R1/i` | 将匹配模型按普通聊天处理；显式空字符串关闭 |
| `PROXY_RETRY_WAIT_MS` | `30000` | WebVPN 登录重定向后等待新凭据 |
| `PROXY_REFRESH_AHEAD_MS` | `1800000` | 到期前多久开始续期 |
| `PROXY_NO_TOKEN_WAIT_MS` | `60000` | 无可用 token 且未配置凭据时的检查间隔 |
| `PROXY_MAX_SLEEP_MS` | `3600000` | 续期调度单次等待上限 |
| `PROXY_KEEPALIVE_MS` | `1500000` | WebVPN 保活间隔 |
| `PROXY_DEBUG_BUDGET` | 未设置 | `1` 显示预算明细和输出上限调整 |
| `PROXY_DIAGNOSTICS` | 未设置 | `1` 开启原始参数对照和有限的失败取证记录 |
| `DUMP_FAILED` | 未设置 | `1` 保存部分上游失败请求 |

`DUMP_FAILED` 会将完整对话保存到状态目录的 `last-failed-request.json`，排障后请关闭并删除文件。

**日志计时**。首字取首个非空思考、正文、工具名称或参数，角色、心跳和用量帧不计入。输出速度为上游 `completion_tokens ÷（收到 [DONE] 的时间 − 首次有效输出时间）`，思考 token 不重复相加，最终校验和缓冲发送不计入分母。非流式聚合和工具参数完整缓冲也使用这段上游时间；日志中的总耗时仍包含整个请求。

重试后的首字仍从原始客户端请求进入代理算起，直到最终尝试的首次有效输出；输出速度只计算最终尝试。上游返回完整 JSON 备用响应时，没有增量观察点，首字和输出速度均显示 `—`。

用量和首字有效且时间差大于零时显示速度，输出 token 为零时显示 `0.0 tok/s`；缺少用量或首字时显示 `输出 —`，零时间差显示 `输出 —（时长为0）`。短间隔可能产生较大数值，网络分块、缓冲和客户端背压都会影响结果；上游未发送思考增量时，计时也不覆盖此前的思考生成。

**网络诊断**。`request` 包含连接、上传和等待响应头，无法进一步区分；`response-body` 表示读取上游响应，`delivery` 表示向客户端交付。日志中的请求体大小不代表已上传字节数。已发送 SSE 响应头时，HTTP 200 后仍可能发生流内错误，需同时查看错误码。

**工具诊断**。校验失败会记录 JSON 错误类别与位置、工具名称、参数字符数、片段数和上游结束原因。`length` 表示上游以长度限制收尾，需结合参数错误判断。实时模式下，“参数转发=一致”表示代理接收的参数与交给 HTTP 写入层的参数相同，不证明客户端已收到。触发工具参数重试时记录 `tool-arguments-retry`，最终成功日志标记 `工具参数重试=1`。新增诊断不保存参数正文、凭据或底层异常中的 URL。

**故障取证**。设置 `PROXY_DIAGNOSTICS=1` 并重启，可在内存中独立对照原始上游参数与代理聚合结果，并记录请求体提交、响应和交付阶段。失败尝试保存到 token 所在目录的 `failure-diagnostics.jsonl`，工具参数重试成功后仍保留首次失败记录。最多保留两份约 1 MiB，不保存参数正文、哈希、凭据或 URL。开启方法和结果含义见[故障取证](docs/DIAGNOSTICS.md)。

</details>

<details>
<summary>接口兼容说明</summary>

- **请求参数**。`max_completion_tokens` 转为 `max_tokens`；开启思考时，低于 512 的输出预算提升到 512。仅保留单个候选回复，不传递 `logprobs` / `top_logprobs`。
- **R1 普通聊天兼容**。学校的 R1 后端遇到 `assistant.tool_calls` 历史会报错。默认移除 R1 请求中的顶层工具声明、工具选择参数，以及 assistant 的 `tool_calls` / `function_call`；保留消息正文、顺序和已有 `tool` / `function` 结果及其关联字段。匹配后的请求按普通聊天处理，包括 `tool_choice: required` 或指定函数的请求，不保证调用工具；需要工具执行时请选择支持原生工具调用的模型。
- **普通聊天模型规则**。`PROXY_STRIP_TOOLS_FOR` 为逗号分隔的规则列表；精确名称和任意位置的 `*` 通配不区分大小写，正则使用 `/regex/flags` 格式并遵循所写 flags，例如 `DeepSeek-*-W8A8,/R[0-9]{1,2}/i`。正则内部的逗号不会分隔规则。未设置时默认 `/R1/i`，显式空字符串关闭；不匹配的模型保留工具字段。
- **思考字段**。原生 `chat_template_kwargs` 优先于顶层思考参数。Qwen 的 `reasoning` 统一为 `reasoning_content`。
- **Qwen 缓存隔离**。`qwen3.8-27b` 每次上游请求使用新的 `cache_salt`，以缓解长对话多语言乱码。凭据重试也会更换，客户端提供的盐值会被替换。隔离缓存可能增加首字等待时间，其他模型的盐值原样转发。
- **响应交付**。常规请求向上游使用 SSE，非流式客户端由代理聚合；兼容上游返回完整 JSON 备用响应。默认实时转发流式正文、思考和原生工具参数。`finish_reason`、用量及 `[DONE]` 在上游正常结束、工具参数通过校验后交付。合法调用若标记为 `stop`，修正为 `tool_calls`；`length` 等其他结束原因保留。实时模式下，仅以 `[DONE]` 结束的合法工具调用补发 `tool_calls`。
- **流式首段暂存**。启用工具参数重试且请求声明 function 工具时，流式 SSE 中可提前交付的首段最多暂存 250 ms、8192 字节或 32 帧。从首个暂存数据帧起计时，任一上限到达或收到 `{` 和 JSON 空白以外的参数字符即释放；正文或思考可能短暂延迟。非流式聚合与 JSON 备用响应没有这项首段暂存。
- **工具参数重试**。默认开启，可用 `PROXY_TOOL_RETRY=0` 关闭重试及首段暂存。仅当上游完整结束、明确以 `stop` 或 `tool_calls` 收尾且尚未发送响应头时，才可能按原请求重新生成一次；流式 SSE 还要求首段暂存尚未释放。所有调用须对应请求中唯一声明的 function 工具，字段、ID 与结束状态无冲突；至少一个参数仅为 `{` 和 JSON 空白，其余参数均为合法 JSON 对象。流式、非流式和 JSON 备用响应采用相同的参数判定，每个客户端请求最多一次，认证重试不重置次数，非流式总时间预算也不因工具参数重试重置。客户端只收到最终尝试；代理不拼接或补全 JSON，不添加提示或执行工具。缺少 `[DONE]` 的 SSE、`length`、网络错误、字段错误以及带键名或键值的残缺参数均不触发重试。重试可能增加一次上游请求和 token 消耗，不能保证消除所有参数错误。
- **错误处理**。上游明确报告的上下文超限返回 400 和 `context_length_exceeded`。已开始发送 SSE 后，断流、超时或工具参数无效会以 `event: error` 和 OpenAI `error` 对象报错，不发送成功结束标记或 `[DONE]`。客户端需丢弃失败调用，不能执行工具或将失败参数带入后续对话。
- **编码完整性**。请求体、SSE 和成功的 JSON 响应遇到非法 UTF-8 时明确报错，避免静默替换字符改变正文或工具参数。请求 JSON 语法错误只报告类别与位置，不回显正文。
- **完整缓冲兼容模式**。设置 `PROXY_TOOL_STREAM=buffered` 并重启代理，可在完整校验后才交付工具参数，适用于需要完整校验后才接收工具参数的客户端。工具参数的完整缓冲不受 250 ms 限制，可提前交付的正文或思考仍可能短暂暂存；长参数仍可能触发客户端空闲超时。客户端仍须处理错误终态。实时模式会交付部分参数，代理无法撤回客户端已接收的数据。

</details>
